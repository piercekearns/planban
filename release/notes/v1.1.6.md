# Planban v1.1.6

Planban v1.1.6 makes Planban feel native in Claude Code desktop and makes the agent handoff work the same in every host.

## Claude Code desktop support

- Planban installs as a Claude Code plugin from GitHub or a local clone: `claude plugin marketplace add piercekearns/planban` then `claude plugin install planban@planban`. The skills are available as `/planban:pb`, `/planban:planban`, `/planban:planban-create`, `/planban:planban-help`, `/planban:planban-tutorial`, and `/planban:planban-feedback`.
- The Board opens in the Claude Code browser pane beside the session, and every open or material change ends with the clickable verified Board URL.
- A session-start hook tells Claude Code when the current project tracks its work in Planban and where its Board is.
- The Planban runtime resolves correctly for Claude Code cache installs, mirroring the existing Codex marketplace recovery.

## Host-neutral agent handoff

- Every MCP create, mutate, status, and get_board result now carries `boardUrl`, `boardUrlVerified`, and a ready-made `userReply` link, so agents in any host return the Board link without needing the skills installed.
- Mutation results are compact: they report `itemCount` instead of the full Item list, keeping large Boards well under host output limits. `planban_get_board` remains the full read.
- The MCP server's initialize instructions state the essential contract: serialized writes, user-controlled completion, one bounded Board presentation attempt per logical batch, and the clickable link in the final reply.
- The `pb`, `planban`, `planban-create`, `planban-help`, and `planban-tutorial` skills and the protocol share one host-neutral critical path with adapter sections for Codex desktop, Claude Code desktop, and other hosts. Codex behaviour is unchanged.
- Generated `.planban/agent-context.md` and the managed `AGENTS.md` block now name the Board URL, the Planban tool names, the handoff rule, and what an agent should do when Planban is not installed for its host: say so once, point to the install steps, and continue.

## Board discovery from linked git worktrees

- Sessions that run in a linked git worktree (Claude Code desktop worktrees, Codex worktrees) now resolve to the Board owned by the repository's main checkout, even though `.planban/` discovery files are usually git-ignored. Discovery never leaks past the repository top.
- Status results report `requestedCwd` and `discoveredVia` when resolution happened.

## Updating

Dependencies are unchanged. Refresh the marketplace and reinstall the plugin so cached skills and hook scripts update, then start a new session. Existing Boards keep their current storage schema; no migration is required. Existing repositories can refresh their generated guidance by re-running `planban init` with `--repo-id` and `--no-agents`.
