# Planban v1.1.5

Planban v1.1.5 fixes first-launch failures and makes board, CLI, and MCP startup use consistent runtime preparation.

## Reliable first launches

- Windows dependency installation uses the shared command-shim boundary, including the CLI, cached board launcher, and MCP bootstrap.
- A valid local checkout takes precedence over marketplace recovery. Recovery is limited to installed plugin caches and checks for a complete Planban runtime.
- The public MCP configuration starts relative to the installed plugin instead of requiring an unresolved checkout placeholder. Existing explicitly configured installations remain supported.
- Dependency installation messages stay on stderr so they cannot corrupt MCP's JSON-RPC responses.
- Fresh-install checks execute MCP initialization, CLI startup, and a verified Board launch with missing dependencies and paths containing spaces.

## Release maintenance

- Updated the locked `qs` and Cloudflare development-tool dependency chain to address dependency advisories.
- Fork pull requests rehearse the upstream release against the contributor repository and branch while still verifying the exact candidate commit.
- Previous-version upgrade correctness is checked separately from unchanged-dependency performance. A dependency-changing release can correctly take the clean-install path without bypassing the steady-state reuse speed gate.
- Windows benchmark pairs run on separate runners and are combined into the same five-sample speed gate. Rehearsals report command and cleanup timings, share the npm cache consistently, and have bounded execution times.

## Updating

This release changes dependencies, so updating from v1.1.4 requires a clean dependency installation. Refresh the marketplace and reinstall the plugin, then start a new Codex session to load its new MCP configuration. Existing Boards keep their current storage schema; no migration is required.
