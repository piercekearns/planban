# Planban v1.1.3

Planban v1.1.3 makes active agent work easier to see, keeps Boards responsive while they reconcile changes, and removes product surface that was competing with the Board's primary job: sight.

## Visible agent activity

- Work Items now show a calm, short-lived activity treatment while an agent reads or changes that specific Item through Planban MCP.
- Overlapping operations coalesce safely, abandoned activity expires automatically, and activity never changes durable Board state.
- A demo-only activity lab remains available for inspecting the visual treatment without changing normal Boards.

## Reliable Board loading

- Replaced long-lived browser event connections with bounded polling of a small live snapshot, preventing abandoned tabs from exhausting the browser's per-origin connection pool.
- Board bootstrap and durable state reads now have explicit timeouts and remain independent of the optional live-update channel.
- Legacy live-update requests receive a terminal response so older tabs stop reconnecting.

## Calmer, portable surfaces

- Simplified the Board header around Home, board switching, Search, See all Items, More, and the real Update Available state.
- Moved Board history, tutorial, feedback, and Archive visibility into quieter secondary controls.
- Replaced card-owned Codex thread launching with portable Item and Group references that can be pasted into any agent surface.
- Added matching copy, move, complete, and archive actions in Item details, with a fixed detail header for long Specs and Plans.
- Relegated Item and document versions to an on-demand History menu while preserving recovery and restoration.
- Made tutorial and feedback language host-neutral and reduced the default MCP catalogue to ordinary planning operations; administration, maintenance, and legacy tools remain available through explicit profiles.
- Added the Planban product constitution to public `main` so future product and agent guidance consistently prioritize sight, low human friction, calm attention, and portability.

## Verification

The release preflight covers version consistency, install-script policy, typecheck, the complete test suite, dependency audit, production build, HTTP behavior, MCP behavior, cached-plugin launch and stale-server repair. Release readiness additionally rehearses a real v1.1.2 to v1.1.3 upgrade while preserving an existing Board and verifying that it remains readable and writable.
