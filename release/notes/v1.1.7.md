# Planban v1.1.7

Planban v1.1.7 stops the Board page reloading in a loop, shows which cards are waiting on you, helps agents keep cards up to date, and makes the install smaller with a clean security audit.

## A steady Board page

- The Board page no longer reloads several times a second. Opening a Board recorded the time it was opened, and that write woke the Board's file watcher, which reloaded the page and repeated the cycle. The open time is now recorded at most once a minute, and the watcher ignores the temporary lock folder that every Board read creates. Real card and doc edits still reach the page.

## Cards that need you, and cards that are out of date

- A card shows **Needs you** when its Next action starts with `Owner:`. The house style and protocol now ask agents to start a Next action with `Owner:` only when the next step is yours.
- Agents see out-of-date warnings for active cards: a pull request the card mentions merged after the card last changed, its Spec or Plan was edited outside Planban, it has been In Progress with no update for five days, a Group's child cards changed after the Group did, or its Next action is waiting on you. `planban_get_card` and `planban_query_cards` return these signals per card, and `planban_status` and `planban_get_board` return a short attention list with the count of Items in progress. The warnings are best-effort and read only local git and Board history; Planban never fetches to compute them.
- The protocol and generated agent context ask agents to fix out-of-date cards they own or touch in the same batch of changes, to keep preview links, branch and session names, commit IDs and merge or deploy state off cards, and to update the In Progress Items that name work when it lands.
- Card create and update results add a gentle note when an Item's metadata grows past about 4 KB.

## Copy Reference and session start

- Copy Reference puts one short line on the clipboard: the card title in quotes followed by an exact reference, `planban:<board>/<item>`. The button shows a tick to confirm the copy. Agents in every host are told how to resolve the reference with `planban_get_card` and to trust the ID over the title.
- The Claude Code session-start hook names the exact agent-context file to read, including from a linked git worktree where the file lives in the main checkout, and adds one line naming cards that are out of date.

## Smaller install and security fixes

- First-run setup no longer installs Cloudflare's Wrangler, Miniflare, workerd and sharp, which nothing in Planban used. That removes 61 packages from every install.
- Locked dependencies are updated to clear the high-severity security audit, including `undici`, `proxy-addr` and `source-map-js`.

## Board history

- Board history now prunes as intended. Planban keeps the newest Board versions, then one per hour for two days and one per day up to the retention limit, and clears a large backlog gradually so it never holds the Board lock for long.

## Docs

- The README, support, contributing and security guides are written for every supported host, with the correct feedback command for Codex and Claude Code. The CLI description is host-neutral, and generated agent context lists all 13 default MCP tools.

## Updating

This release changes dependencies, so updating from v1.1.6 runs a clean dependency installation. Refresh the marketplace and reinstall the plugin so cached skills, hook scripts and MCP instructions update, then start a new session. Existing Boards keep their current storage schema; no migration is required. Existing repositories can refresh their generated guidance by re-running `node "$PLANBAN_ROOT/bin/planban.mjs" init` with `--repo-id` and `--no-agents`.
