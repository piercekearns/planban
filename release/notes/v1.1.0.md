# Planban v1.1.0

Planban 1.1.0 adds a one-level Groups and Items model. Use a Group when several independently completable Items contribute to one larger outcome.

## Groups and Items

- A Group stays on the Main Board and has its own purpose, Status, priority, and evidence.
- Each Item keeps its own Status, priority, documents, history, and next action.
- The Group Workspace shows the Group and its Items together.
- Move and rank Items within a Group without changing their identity or documents.
- Move a card to another Status by dropping it on the destination column, even when that column is collapsed or hiding its cards.
- Create and manage the same structure through the board UI, HTTP API, CLI, and MCP.
- Existing flat boards load as Items in their current visible order. Planban upgrades stored data only when the board next changes.
- Legacy Programme and Deliverable commands remain available as compatibility aliases. Current guidance and discovery use Group and Item.

## Clearer records for people and agents

- Planban's installed guidance now separates current state, next action, intended outcome, execution detail, and evidence.
- Summaries state what is true now. Next actions state the next concrete step or decision.
- Specs and Plans retain the detail that agents need without duplicating the card front.
- The first-run tutorial explains when to create a Group and when to keep an Item independent.

## Reliability

- Fresh local Codex installations record the Node executable that configured the plugin, so the Planban MCP process can start without relying on the host shell path.
- MCP status checks now accept either a registered board id or an absolute repository path, consistent with the other board tools.
- The agent-led feedback workflow from v1.0.5 remains included.

## Migration and compatibility

The v1.1.0 release rehearsal starts from the public v1.0.5 tag. It checks board migration, plugin update, API, CLI, MCP, persistence, and generated public-package behavior before publication.
